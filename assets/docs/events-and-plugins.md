# イベントとプラグイン統合

## SystemEvent オブジェクト

- `SystemEvent` はイベント名・パラメータ・収集された出力・伝播フラグを保持します。プラグインは UI アラートの追加、出力の追記、伝播停止などをこの API 経由で行います。

## ディスパッチの仕組み

- `DocumentParser::invokeEvent()` がプラグインキャッシュからリスナーを解決し、既定プロパティを注入した上でプラグインコードを実行します。`$modx->event->stopPropagation()` が呼ばれると後続のプラグインがスキップされます。
- プラグイン定義とイベント紐付けは `synccache::buildCache()` が生成する `siteCache.idx.php` に保存され、データベースへの追加アクセスを避けます。
- キャッシュにはプラグインコード・プロパティ・エラーレポート設定も含まれ、再利用時の初期化コストを削減します。

## フロントエンドイベントの時系列

1. `OnWebPageInit`: リクエストのサニタイズとリソース解決が完了した直後に実行されます。
2. `OnLoadWebPageCache`: キャッシュ済みページを利用する前に発火し、キャッシュ参照を抑止する機会を提供します。
3. `OnLoadWebDocument`: ドキュメントオブジェクトが構築された直後で、テンプレート解析の前に実行されます。
4. `OnParseDocument`: `parseDocumentSource()` の各ループで呼ばれ、`documentOutput` を検査・変更できます。
5. `OnLogPageHit`: 訪問ログ取得が有効な場合に `outputContent()` 内で呼び出されます。
6. `OnWebPagePrerender`: レスポンス出力の直前で、最終的なプレースホルダー調整に対応します。
7. `OnBeforeSaveWebPageCache`: `postProcess()` 内でキャッシュ書き込みの前に呼ばれ、キャッシュ処理をスキップする判断を行えます。
8. `OnWebPageComplete`: レスポンス完了後、静的キャッシュ経由のショートサーキットも含めて発火します。

## プラグイン実装のヒント

- ヘルパーの `evo()->invokeEvent()` を利用し、常に共有の `DocumentParser` インスタンスを介してイベントを発行する。
- 同一イベントで複数回実行される可能性があるため、`$modx->event->name` や `$modx->event->activePlugin` を確認して副作用を制御する。
- リッチテキストのエディタ（TinyMCE など）は、内容が変わったら元の欄（textarea）へ bubbles の `input` イベントを送る。iframe の中の変更はフォームから見えないため、フォームの `input` を拾う仕組み（ライブプレビューの自動更新など）はこれに頼る。
- テンプレートへデータを渡す場合は `$modx->setPlaceholder()` を用いてプレースホルダーに値を仕込み、標準の解析サイクルに乗せる。

## ファイルブラウザのイベント

ファイルブラウザ（`manager/media/browser/evo/api.php`）には、範囲が 2 つあります。投稿画面などから開いてファイルを選ぶ範囲（ピッカー）と、メニューの「ファイルマネージャー」（`index.php?a=31`）の範囲（管理モード）です。アップロードのイベントは範囲ごとに別の名前で、どちらも同じ値を渡します。

| 範囲 | イベント | 発火する場面 |
|---|---|---|
| ピッカー | `OnFileBrowserUpload` | アップロードで 1 ファイルを保存するたび（同じ名前があれば `名前(1).拡張子` のような空いている名前で保存する）と、画像を編集して別名で保存した後。画像の上書き保存では発火しません |
| 管理モード（ファイルマネージャー） | `OnFileManagerUpload` | アップロードで 1 ファイルを保存するたび（同じ名前のファイルがあれば、確認のうえ上書きして保存し、そのときも発火します）と、画像を編集して別名で保存した後。画像の上書き保存では発火しません |

- 渡す値は `filepath`（保存先フォルダの確かめた実パス）と `filename`（保存したファイル名）です。`filepath` は末尾に `/` が付き、区切りは Windows でも `/` です。
- `OnFileManagerUpload` は旧ファイル管理から引き継いだイベントで、付けてあるプラグインはそのまま動きます。ただし旧では `filepath` がリクエストで受けたパス（末尾の `/` なし）でしたが、今は上の形（確かめた実パス、末尾に `/`）です。プラグインが `filepath` と `filename` をつなぐときは、末尾の `/` の有無に左右されない書き方にします。
- 保存先は、管理モードでは設定 `filemanager_path` の下のどのフォルダでもありえます。ピッカーでは設定 `rb_base_dir` の下の種類のフォルダ（`images`・`media`・`files`）の中です。
- `OnFileBrowserUpload` は新しいイベントなので、既存のサイトのイベント一覧へは、アップデーター（`install/`）で上げると、イベント名の同期で追加されます（仕組みは `migrations.md`。同梱イベントの番号の決まりも同じ文書にあります。`php evo migrate` だけでは入りません）。既存のプラグインへの紐付けは自動では付かないので、プラグインの編集画面でこのイベントを選びます（`OnFileManagerUpload` は元からあるイベントです）。
