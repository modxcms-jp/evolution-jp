# パスワードの決まりと設定の画面

管理画面の利用者（管理ユーザー）と、管理画面で編集する Web ユーザーのパスワードの決まり、設定の画面の作り、保存と照合の形。
NIST SP 800-63B-4（Section 3.1.1 Passwords）に基づく段階的な改善として作っている。ブロックリストの照合と最小 15 文字を満たしていないので、準拠とは表記しない（下の「NIST SP 800-63B-4 との対応」）。

## 正本

| 何を | どこで |
| --- | --- |
| 文字数・バイト数・自動生成の文字数と文字集合・推測されやすい値の判定・ハッシュの作り方と照合・差し戻しで残さない項目名 | `manager/includes/password_policy.class.inc.php`（`EvoPasswordPolicy`）。管理画面の言語や DB に頼らないので、インストーラーからも読む |
| 管理画面のエラー文（理由の名前 → 言語ファイルの文） | `ex_managerapi.php` の `passwordError()`。インストーラーは `install/functions.php` の `installerAdminPasswordError()` |
| 保存用のハッシュ | `manager()->hashPassword()`（中身は `EvoPasswordPolicy::hash()`）。インストーラーの管理者は `EvoPasswordPolicy::hash()` を直に使う |
| 画面の行（HTML） | `manager/actions/permission/mutate_user/user_form_rows.php` の `userFormPasswordRow()` |
| 画面の動き（JS） | `manager/media/script/password-field.js`（`EvoPasswordField`）。決まりの数と文字集合は `EvoPasswordPolicy::clientConfig()` を `js_value()` で受ける |
| 見た目 | `manager/media/style/common/forms.css` の `.password-setting*` |

数（8・15・20・72 など）を画面・JS・言語ファイルに書き込まない。言語ファイルの文は `%1$d`（最小）・`%2$d`（推奨または上限）や `%count%` などの差し込みで受ける。

## 決まり

| 項目 | 内容 |
| --- | --- |
| 最小 | 8 文字（`MIN_LENGTH`）。これ未満は保存しない |
| 推奨 | 15 文字（`RECOMMENDED_LENGTH`）。8〜14 文字は入力中に警告するが、保存は妨げない。15 文字以上でも「強い」「安全」とは表示しない（文字数の案内と強さの評価は別のもの） |
| 上限 | NFC にそろえた後の UTF-8 で 72 バイト（`MAX_BYTES`）。bcrypt は先頭の 72 バイトしか照合しないので、超える値は切り捨てずに断る。半角だけなら 72 文字、全角だけなら 24 文字 |
| 数え方 | Unicode のコードポイントの数（バイト数ではない） |
| 使える文字 | 制御文字（C0・DEL・C1）以外のすべて。空白・記号・全角の文字も使える。正しくない UTF-8 は断る |
| 文字種の組み合わせ | 強制しない（数字だけ・英字だけも可） |
| 加工 | しない。`trim()`・大文字小文字の変換・切り捨てをしない。前後の空白も文字のうち |
| 推測されやすい値 | 全体がログイン名・メールアドレス（とその @ の前）・氏名・サイト名と同じ値（英字の大文字小文字は区別しない）、同じ文字や 4 文字以内の単位の繰り返し、1 つずつ増える・減る並び（数字は 9 の次を 0 とする）を断る。部分に含むだけなら断らない |
| 定期的な変更 | 求めない |
| 既存のパスワード | 決まりは新しく設定・変更するときだけに当てる。8 文字未満の既存のパスワードでもログインできる。アップデートで変えない |

頻出・漏えい済みのパスワードの一覧（ブロックリスト）・辞書との照合と、外部のサービスへの問い合わせはしていない。配布の大きさを抑えるためで、v1.5.0 以降で検討する。

## 正規化

- intl の `Normalizer` があれば、設定のときもログインのときも NFC にそろえてからハッシュ・照合する（`EvoPasswordPolicy::normalize()`）。無ければそろえない。
- 照合は「NFC にそろえた値 → 送られたままの値」の順に試す（`EvoPasswordPolicy::verify()`）。そろえていない値で保存したハッシュも照合でき、合えば NFC の値で作り直す。
- NFKC ではなく NFC にする。NFKC は全角の英数字を半角にそろえるが、NIST SP 800-63B-4 は NFC を挙げているため。全角と半角は別の文字になるので、全角の英数字・空白を入れたときは入力中に注意を出す。
- intl のある環境で全角の文字を含むパスワードを設定した後、intl の無い環境へ移すと、入力の形によってはログインできないことがある（日本語の入力は通常 NFC なので、ほとんど起きない）。

## 保存と照合

- 管理ユーザー: `password_hash()`（`PASSWORD_DEFAULT`、今は bcrypt）。ソルトとコストは値に含まれる。ログインのたびに `password_needs_rehash()` を見て作り直す。古い形（phpass・MD5・v1）は、ログインに成功したときに今の形へ作り直す（`login.processor.functions.php`）。
- インストーラーの管理者: `EvoPasswordPolicy::hash()` で入れる。
- Web ユーザー: ソルトのない MD5 のまま（`save_web_user.processor.php`）。表側のログイン（`assets/snippets/weblogin`）と `document.parser.subparser.trait.php` の `changeWebUserPassword()` が MD5 で照合するため、保存の形だけを変えるとログインできなくなる。直すには、照合の側を管理ユーザーと同じ「形を見分けて照合し、合えば作り直す」にそろえる必要がある（下の「残りの課題」）。
- POST の `sanitize_gpc()` は、パスワードの欄も対象になりうる（`save_document` 権限の無い利用者の管理画面の POST）。`[[`・`{{`・`&#38;` を含むパスワードで、権限の無い利用者の自己変更とそのログインを Docker で確かめ、設定と照合で値が食い違わないことを見た。

## 画面

4 つの画面が同じ行（`userFormPasswordRow()`）を使う。

| 画面 | 状態（第 1 引数） | 初めの表示 |
| --- | --- | --- |
| 管理ユーザー・Web ユーザーの新規（`a=11`・`a=87`） | `new` | 欄を開き、英大小文字と数字の 20 文字を伏せ字で生成する |
| 管理ユーザー・Web ユーザーの編集（`a=12`・`a=88`）、プロフィール（`a=74`。`save_password` 権限があるとき） | `set` | 「設定済み［パスワードを変更］」。押すと欄を開く（自動では生成しない）。「変更を取り消す」で値を捨てて閉じる |
| プロフィールで `save_password` 権限が無いとき | `readonly` | 「設定済み」だけ |
| パスワードの変更（`a=28`。パスワード再設定のリンクの行き先） | `change` | 欄を開く。自動では生成しない |

- 並び: 欄（右端の内側に目のアイコン）とコピー → 決まりの一言「8文字以上（15文字以上を推奨）」（詳しい説明はツールチップ）→ 文字数の案内 → 自動生成のオプションの枠（文字数のスライダー 8〜64 と ±ボタン、「記号を含む」初期オフ・「大文字を含む」「数字を含む」初期オン、右下に主ボタンの「自動生成」）→ 保存後の注意 → 「変更を取り消す」（`set` のときだけ。枠の外の右下）。小文字は常に使う。
- 欄は 1 つ（確認用の欄は無い）。`autocomplete="new-password"`、用途に合わせたプレースホルダー。貼り付け・パスワード管理ツールを妨げない。
- 目のアイコンはログイン画面と同じもの（`manager/media/style/common/password_toggle_icons.tpl`。共通の `login.tpl` もここから読む）。状態は `aria-pressed` で表し、ラベルは言語キー `show_password`（ログイン画面と同じ）。テーマの login.tpl は、それぞれのアイコンのまま。
- コピー（アイコンは `icons_resource_duplicate`）は伏せ字のまま写す。欄が空なら無効。Clipboard API が使えない（HTTP のサイト）ときは、画面の外の textarea から写す。失敗しても欄を表示に切り替えない。知らせの文にパスワードを含めない。
- 自動生成（アイコンは `icons_refresh`）は Web Crypto（`crypto.getRandomValues`）だけで行い、剰余の偏りが出ないよう引き直す。オンにした文字種が欠けたら全体を作り直す（位置を決め打ちしない）。Web Crypto が無ければボタンを止め、ほかの方法には替えない。サーバーでは生成しない（平文が応答の HTML に載らない）。
- オプションを変えただけでは欄の値を変えない。自動生成のボタンを押したときだけ上書きする。初めと自動生成の後は伏せ字にする。
- 「パスワードを変更」で欄を開いたとき、欄へはフォーカスしない（ブラウザの入力候補の一覧が開いて欄を隠すため）。フォーカスは自動生成のボタンへ移す。「変更を取り消す」は、値を捨て、伏せ字とオプションを初めに戻して閉じる。
- 文字数の案内は入力中に欄の下へ出す。8 文字未満は「8文字以上で設定してください」（エラー）、8〜14 文字は「15文字以上を推奨します」（警告）、15 文字以上は出さない。空の欄には、送るまで何も出さない。
- 送る値は `newpassword`（変えるとき 1）と `userpassword`。欄を閉じているときは欄を無効にして送らない。新規は常に 1。
- 8 文字未満・空・上限を超える値は、送信を止めて欄の下に知らせる。サーバーも同じ決まりで確かめる（クライアントを迂回しても断る）。
- 保存後の注意は「保存後はパスワードを確認できません。必要に応じて保存前にコピーしてください。」。他人のパスワードを設定する画面（自分のプロフィール・`a=28`・自分の編集以外）では、本人へ安全な方法で伝えるよう添える（`userFormPasswordRow()` の `self`）。
- JS が動かないとき: 新規は空の欄に手で入力できる。編集の画面ではパスワードを変えられない（`a=28` は欄が開いているので変えられる）。
- 狭い画面では欄が縮み、ボタンは折り返す。ユーザーの編集画面は、表のほかの欄（350px）があるので、600px より狭いと画面全体が横にはみ出す（この部品だけの問題ではない）。

## 露出させないこと

- 保存の後にパスワードを表示しない。メールで送らない。通常の保存と同じ行き先（`EvoFormFlow::afterSaveUrl()`）へ戻す。自分のパスワードを変えたときは、ログインし直してもらう。
- 入力エラーの差し戻し（`saveFormValues()`）では、`EvoPasswordPolicy::FORM_FIELDS` の項目をセッションに残さない。差し戻した画面では欄を空で開き、消したことを知らせる。
- URL・ログ・ブラウザのストレージに残さない。
- `passwordgenmethod`・`passwordnotifymethod`・`specifiedpassword`・`confirmpassword` を送られても、生成・メール・表示はしない（読まない）。
- パスワードをメールで知らせないので、設定 `signupemail_message` は持たない（既存のサイトの DB の行は残るが、本体は読まない）。`websignupemail_message` は外部のスニペットが読みうるので設定画面に残す。

## イベント

| イベント | `userpassword` |
| --- | --- |
| `OnManagerSaveUser`・`OnWebSaveUser` | 新規と、パスワードを変えた保存は新しいパスワード（平文）。変えない保存は空文字 |
| `OnManagerChangePassword`（ユーザーの編集）・`OnWebChangePassword` | 新しいパスワード（平文）。変えたときだけ発火する |
| `OnManagerChangePassword`（`a=28` の変更の画面） | 保存したハッシュ（平文ではない）。同じイベントで中身が違う |
| `OnBeforeManagerLogin`・`OnManagerAuthentication`・`OnManagerLogin` | ログインで送られた値（平文） |

平文を渡すのをやめるには、プラグインが平文を使っている用途（外部のサービスとの同期など）の代わりを用意し、非推奨の期間を置く必要がある（`deprecations.md`）。今は渡し方を変えていない。

## NIST SP 800-63B-4 との対応

区分は SHALL（必須）・SHOULD（推奨）。状態は「対応」「一部」「未対応」「対象外」。

| 項番 | 区分 | 要件 | 状態 | 実装・理由 |
| --- | --- | --- | --- | --- |
| 3.1.1.1 | SHALL | パスワードは利用者が選ぶか、CSP が無作為に割り当てる | 対応 | 手入力と Web Crypto の自動生成 |
| 3.1.1.1・3.1.1.2 | SHALL NOT | 組み合わせの規則を課さない | 対応 | 文字種を問わない |
| 3.1.1.2 | SHALL | 単一要素では 15 文字以上 | 未対応 | 最小 8 文字・推奨 15 文字（警告のみ）。多要素認証が無いので 15 文字が必要。最小を 15 にするか、多要素認証を入れる（8 文字以上で可）のが今後の案 |
| 3.1.1.2 | SHOULD | 最大 64 文字以上を許す | 一部 | 半角は 72 文字まで。全角は 24 文字まで（bcrypt の 72 バイト）。全角も 64 文字にするには、前段のハッシュ（HMAC など）か Argon2id への移行が要る |
| 3.1.1.2 | SHOULD | 印字できる ASCII と空白を受ける | 対応 | |
| 3.1.1.2 | SHOULD / SHALL | Unicode を受け、コードポイントを 1 文字と数える | 対応 | `EvoPasswordPolicy::length()` |
| 3.1.1.2 | SHOULD | NFC にそろえてからハッシュする | 一部 | intl があるときだけ |
| 3.1.1.2 | SHOULD | Unicode の表示の違いを案内する | 対応 | 全角の英数字の注意、決まりの説明 |
| 3.1.1.2 | SHALL NOT | 定期的な変更を求めない | 対応 | |
| 3.1.1.2 | SHALL | 侵害の証拠があれば変更させる | 未対応 | 管理者が変える・ブロックする以外の仕組み（次のログインで変更を求める印）が無い |
| 3.1.1.2 | SHALL NOT | 未認証の利用者に見えるヒント・秘密の質問 | 対応 | 無い |
| 3.1.1.2 | SHALL | 全体を照合し、切り捨てない | 対応 | 72 バイトを超える値を断る |
| 3.1.1.2 | SHALL | 設定・変更のときにブロックリストと照合し、理由を示す | 一部 | ログイン名などと同じ値・単純な並びだけ。頻出・漏えい済みの一覧は無い（v1.5.0 以降） |
| 3.1.1.2 | SHOULD | ブロックリストの大きさを試行の上限に見合わせる | 未対応 | 同上 |
| 3.1.1.2 | SHALL | 強いパスワードの選び方を案内する（特に断ったとき） | 対応 | `password_advice`、推奨の文字数の警告 |
| 3.1.1.2・3.2.2 | SHALL | 失敗の回数を制限する（連続 100 回以下で無効にする） | 一部 | 既定は 5 回で 10 分止める（`failed_login_attempts`・`blocked_minutes`）。時間がたつと解けるので、通算の回数の上限は無い |
| 3.1.1.2 | SHALL | パスワード管理ツールと自動入力を許す | 対応 | `autocomplete`、貼り付けを止めない |
| 3.1.1.2 | SHOULD | 貼り付けを許す | 対応 | |
| 3.1.1.2 | SHOULD | 送る前に表示できる選択肢を用意する | 対応 | 設定の画面とログインの画面に表示の切り替え |
| 3.1.1.2 | SHALL | 認証された保護された通信路で求める | 一部 | HTTPS はサイトの設定しだい。HTTP では通信路の要件を満たさない（本体は強制しない） |
| 3.1.1.2 | SHALL | オフラインの攻撃に強い形で、ソルトとハッシュで保存する（ソルトは 32 ビット以上） | 一部 | 管理ユーザーは bcrypt（ソルト 128 ビット）。Web ユーザーはソルトのない MD5 |
| 3.1.1.2 | SHOULD | コストをできるだけ高くし、上げていく | 一部 | `PASSWORD_DEFAULT` の既定のコスト。ログイン時に作り直す |
| 3.1.1.2 | SHOULD | SP 800-132 の承認された方式 | 未対応 | bcrypt は SP 800-132 の方式（PBKDF2）ではない |
| 3.1.1.2 | SHOULD | 方式とコストをパスワードごとに残す | 対応 | `password_hash()` の値に含まれる |
| 3.1.1.2 | SHOULD / SHALL | 秘密の鍵（ペッパー）で鍵付きのハッシュを重ねる（使うなら鍵は別に保管する） | 未対応 | 鍵の置き場所・バックアップ・移行の設計が要る |

## 残りの課題

- 頻出・漏えい済みのパスワードのブロックリスト（v1.5.0 以降。配布の大きさとの兼ね合い）
- 最小 15 文字、または多要素認証
- Web ユーザーの保存の形（ソルトのない MD5）を `password_hash()` にする。weblogin・`changeWebUserPassword()`・外部のログインの部品の照合を、形を見分けて照合し合えば作り直す形にそろえる
- 表側の weblogin の登録・変更の画面に、同じ決まりを当てる
- 侵害の証拠があるときに、次のログインで変更を求める仕組み
- 失敗の回数の通算の上限
- 全角の文字でも 64 文字を受けるための、前段のハッシュか Argon2id への移行
- `a=28` の `OnManagerChangePassword` がハッシュを渡す点の扱いと、イベントで平文を渡すことの段階的な廃止
- インストーラーは、手順をまたいで管理者のパスワードをセッションに持ち、入力の画面へ戻るときに欄の値として HTML に出す（インストールの間だけ）
