# テンプレートと要素の解析手順

## テンプレート解決

- `_getTemplateCode()` がテンプレート継承を辿り、`@FILE` などのバインディングを処理しながら親テンプレートのプレースホルダーを展開します。
- テンプレート変数（TV）はドキュメント取得時に同時に読み込まれ、`[*tvName*]` のようなトークンはコアフィールドと同じパスで評価されます。

## 解析パス

`parseDocumentSource()` は MODX タグがなくなるまで定められた順序で繰り返し実行されます。条件タグ、インラインフィルター、TV、システム設定、チャンク、スニペット、プレースホルダー、URL の順で解析され、各周回で `OnParseDocument` イベントが発火します。

## 要素種別

- **ドキュメントフィールド / TV**: `mergeDocumentContent()` がフィールド参照やフォールバック（`field|altField`）、親参照（`field@parent`）、モディファイアチェーン、`@` バインディングを処理します。TV の配列値は既定で `tvProcessor()` によって整形されます。
- **システム設定**: `mergeSettingsContent()` が `[(setting)]` を置換し、モディファイアにより算出値を提供します。
- **チャンク**: `mergeChunkContent()` がチャンク本文を読み込み、パラメータ付きプレースホルダーや入れ子のタグを再帰的に解析します。リテラルセクションは尊重されます。
- **プレースホルダー**: `mergePlaceholderContent()` がネストしたタグを先に評価し、その後 `[+placeholder+]` を置換します。スニペットやプラグインが投入した値が対象です。
- **スニペット**: `evalSnippets()` が `[[Snippet?param=value]]` をトークナイズし、プロパティ読込後に PHP を実行します。`[[!Snippet]]` は非キャッシュとして扱われ、`parseNonCachedSnippets()` によりランタイム評価へ書き換えられます。
- **リクエストなどの値**: `evalSnippets()` は `[[$_GET['key']]]` のように `$_` で始まるタグを `_getSGVar()` で値に置き換えます（`$_GET`・`$_POST`・`$_REQUEST`・`$_COOKIE`・`$_SERVER`・`$_SESSION`。`[[$_GET['a']['b']]]` で入れ子、`[[$_GET]]` のようにキーを省くと全体を `print_r()` で出します）。
  - `$_REQUEST` のタグは `anyv()` から読みます。GET・POST だけで、cookie は読みません。
  - `$_GET`・`$_POST`・`$_REQUEST` のタグの値は、HTML として解釈されないように、修飾子を当てた後で `hsc()` します。修飾子を当てたときは、`:hsc`・`:esc` などで既に文字参照になったもの（値に元からあった `&amp;` なども含む）を二重にしません。
  - 差し込む値にタグの記号を残しません。`$_GET`・`$_POST`・`$_REQUEST` のタグの値には、システム設定 `sanitize_gpc` やフロントの `$_POST` かどうかに依らず、起動時と同じ無害化（`sanitize_gpc()`）を修飾子の前にかけます（修飾子が値をタグとして解析しないため）。起動時と同じなので、`<script` や `&#数字;` も崩れます。修飾子を当てたときは、その結果にもタグの記号を崩す処理（`breakTagDelimiters()`。`sanitize_gpc()` の中でタグの記号を崩す部分）をかけます（`:urldecode` などで戻した値のため）。`raw` で外れるのは HTML のエスケープだけで、タグの記号は `raw` でも崩します。
  - 崩すのは修飾子の列の前と後だけです。値を戻す修飾子（`:urldecode`・`:base64_decode`・`:html_decode` など）の後に、値をタグとして解析する修飾子（`:summary`・`:addbreak`、サイトで足した phx の修飾子など）を続けると、戻したタグが列の途中で解析されます。この並べ方はしません。
  - HTML のエスケープを外すときは、最初の修飾子に `raw` を書きます（`[[$_GET['key']:raw]]`）。修飾子で HTML や属性を組み立てるとき（`:then` に `<b>` や `selected="selected"` を書く、`:ifempty` にチャンクを書く、`:nl2br` など）も `raw` が要るので、値を出す部分は自分でエスケープします（`[[$_GET['key']:raw:hsc:nl2br]]`）。条件タグ（`<@IF:[[$_GET['key']]]>`）はエスケープした後の文字列で判定するので、値で判定するときも `raw` を書きます。修飾子の結果に残ったタグ（`:then` に書いたものや `:ifempty` に書いたチャンクの中の `[~id~]`・`[+placeholder+]` など、修飾子の中で解析されずに残るもの）も崩れるので、リンクなどはこのタグの外に書きます。
  - `$_COOKIE`・`$_SERVER`・`$_SESSION` のタグはエスケープしません。
  - キャッシュするページでは、置き換えた値もキャッシュに入ります。ページキャッシュのファイルは、タイプ 1 では `id` を除く GET の値ごと（`genQsHash()`）、タイプ 2 では URI ごとに分かれ、POST の応答はキャッシュしません。
- **修飾子と配列の値**: 修飾子は文字列の値を受ける前提です。値が配列のとき（`?b[]=x` のように送られたリクエストの値、配列を入れたプレースホルダー、配列を返すスニペットなど）は、`phxFilter()` が修飾子を当てずに空にします（`:ifempty` なども当てません）。修飾子の無いタグでも配列は差し込まれず空になるので、それとそろえています。値を使わずに文書の項目を読む `id(` で始まる修飾子の列だけは、配列でもそのまま当てます。TV の値は、修飾子の前に `tvProcessor()` で文字列にするので、この扱いになりません。

## 条件タグとコメント

- 条件ブロック（`<@IF>` / `<!--@IF-->`）は `mergeConditionalTagsContent()` により正規化され、`_parseCTagCMD()` が内部の MODX タグも含めて判定します。
- `<!--@IGNORE-->` や `<!--@MODX:...-->` で囲まれたコメントタグも同じ解析ループで処理され、必要なパスでのみ展開されます。

## 出力調整

- `outputContent()` が登録済みのスクリプトやインラインコードを挿入し、残留する MODX マーカーを整理した上で `OnWebPagePrerender` を発火します。
- ベンチマーク用プレースホルダー（`[^q^]` など）は `mergeBenchmarkContent()` により最終段階で埋め込まれます。
