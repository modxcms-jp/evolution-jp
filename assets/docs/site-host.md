# サイトのホスト（site_host / SITE_HOST）

サイトの URL（`MODX_SITE_URL`。テンプレートの `[(site_url)]`、リンク、リダイレクト、メールのリンク）を組み立てるときに使う、正式なホスト名（必要ならポート付き）。

## 決まり方

`init::get_site_url()`（`manager/includes/initialize.functions.inc.php`）が、次の順で決める。

1. `define-path.php` で `MODX_SITE_URL` を定義していれば、それを使う（この先の判定は通らない）
2. `.env`（またはサーバーの環境変数）の `SITE_HOST`
3. システム設定の「サイトのホスト」（`site_host`）。保存すると `temp/cache/basicConfig.php` に `$site_host` として書き出され、初期化のときに読まれる
4. どれも無ければ、今までどおりリクエストから決める（`init::get_host_name()`）

2 か 3 があれば、どのホスト名・ポートでアクセスされても、サイトの URL は常にそのホストで作る。スキーム（http / https）は今までどおりリクエストから決める（`init::is_ssl()`）。

インストール中（インストーラの中、または `manager/includes/config.inc.php` が無いとき）は 3 を読まず、アクセスされたホストをポート込みで使う。入れ直す前の古い `basicConfig.php` が残っていても、インストールを進められるようにするため。

## 書式

`ホスト名[:ポート]`。1 つだけ書く。

- 例：`example.com`、`www.example.com`、`localhost:8181`、`[::1]:8080`
- 大文字は小文字にそろえる
- 既定のポート（http は 80、https は 443）は省く。`example.com:80` は `example.com` として扱う
- スキーム（`http://`）やパスは書かない。形式の正しくない値は、未設定と同じ扱いになる（システム設定では空として保存される）

80 番（https は 443 番）以外のポートで動かすときは、ポートも書く。リバースプロキシの内側で動かしていて、表からは 443 番でアクセスされる場合は、ポートを書かない。

## 設定のしかた

- 管理画面：「システム設定」→「サイト」→「サイトのホスト」。新規インストールでは、インストールしたときのホストが自動で入る（`.env` で `SITE_HOST` を決めている場合を除く）。アップデートでは値を足さない
- `.env`：サイトのルートの `.env` に `SITE_HOST=example.com` と書く。システム設定より優先される

設定していないサイトでは、システム設定の画面に、設定をすすめる案内が出る。今開いているホストと違う値が設定されているときは、注意が出る。

## 設定を誤ったときの戻し方

管理画面に入れなくなった場合は、次のどちらかで戻せる。

- `.env` に正しい `SITE_HOST` を書く（システム設定より優先される）
- DB の `modx_system_settings`（接頭辞はサイトによる）で `setting_name='site_host'` の値を空にし、`php evo cache:clear` などで `basicConfig.php` を作り直す（空なら今までの動きに戻る）

## 補足

- ページのキャッシュには、サイトの URL を含む HTML が残る。設定を変えたら、キャッシュを消す（システム設定の保存で消える）
- システム設定の `site_url` は、`basicConfig.php` に書き出されるが、サイトの URL の決定には使われていない。ホストを固定したいときは `site_host` を使う
