# サイトのURL（fixed_site_url / SITE_URL）

サイトの URL（`MODX_SITE_URL`。テンプレートの `[(site_url)]`、リンク、リダイレクト、メールのリンク）を固定するための設定。

## 決まり方

`init::get_site_url()`（`manager/includes/initialize.functions.inc.php`）が、次の順で決める。

1. `define-path.php` で `MODX_SITE_URL` を定義していれば、それを使う（この先の判定は通らない）
2. `.env`（またはサーバーの環境変数）の `SITE_URL`
3. システム設定の「サイトのURL」（内部名 `fixed_site_url`）。保存すると `temp/cache/basicConfig.php` に `$fixed_site_url` として書き出され（パスは使わないので、スキーム・ホスト・ポートだけを書く）、初期化のときに読まれる
4. どれも無ければ、今までどおりリクエストから決める（`init::get_host_name()`）

2 か 3 があるときは、次のように URL を作る。

- ホストとポート：設定した URL のものを使う。どのホスト名・ポートでアクセスされても変わらない
- http / https：`https://` と書いたときは常に https。`http://` と書いたときは、今までどおりアクセスに合わせる（`init::is_ssl()`）
- パス：設定した URL のパスは使わず、今までどおりサイトの設置場所から決める（`MODX_BASE_URL`）

インストール中（インストーラの中、または `manager/includes/config.inc.php` が無いとき）は 3 を読まず、アクセスされたホストをポート込みで使う。入れ直す前の古い `basicConfig.php` が残っていても、インストールを進められるようにするため。

`config('site_url')` と `[(site_url)]` は、これまでどおり、決まった `MODX_SITE_URL` を返す。

## 書式

`http://ホスト名[:ポート]/` または `https://ホスト名[:ポート]/`。

- 例：`https://example.com/`、`http://localhost:8181/`、`http://[::1]:8080/`
- スキームを省くと `http://` とみなす
- ホストは小文字にそろえ、スキームの既定のポート（http は 80、https は 443）は省く
- 形式の正しくない値（ポートが 1〜65535 の範囲外、ホスト名の形が不正など）は、未設定と同じ扱いになる（システム設定では空として保存される）。`.env` の値が不正なときは、システム設定の値を使う

80 番（https は 443 番）以外のポートで動かすときは、ポートも書く。リバースプロキシの内側で動かしていて、表からは https の 443 番でアクセスされる場合は、`https://example.com/` と書く（内側のポートは書かない）。

## 設定のしかた

- 管理画面：「システム設定」→「サイト」→「サイトのURL」。新規インストールでは、インストールしたときの URL が自動で入る（`.env` で `SITE_URL` を決めている場合を除く）
- `.env`：サイトのルートの `.env` に `SITE_URL=https://example.com/` と書く。システム設定より優先される

設定していないサイトでは、システム設定の画面に、設定をすすめる案内が出る。今開いているホストと違う値が設定されているときは、注意が出る。

## 以前の site_url 設定からの移行

以前のシステム設定「サイトのURL」（`site_url`）は、`basicConfig.php` に書き出されて一部のリダイレクトに使われていたものの、URL の決定には使われていなかった。設定を保存するたびにそのときの URL が自動で保存されていたため、DB には利用者が意識していない値が残っていることがある。

- アップデートでは、DB の `site_url` の行を消す。`fixed_site_url` は足さないので、既存のサイトの動きは変わらない（URL を固定したいときは、管理画面で設定する）
- 既存のサイトを 80 番（https は 443 番）以外のポートで動かしている場合は、設定しないと今までどおり URL からポートが落ちる。管理画面か `.env` で、ポート付きの URL を設定する
- 設定の保存では `site_url` を保存しない
- リダイレクト（`sendRedirect()`）は `MODX_SITE_URL` を使う

## DB の取り込み

`php evo db:import` と、管理画面のバックアップからの復元（`EvoBackupManager::restore()`）は、どちらも取り込み先の `fixed_site_url` を残す。

- 取り込み先に値があれば、その値に戻す（取り込むダンプに行が無くても戻す）
- 取り込み先に値が無ければ、取り込んだ値（別の環境の URL）は使わず、未設定にする

## 設定を誤ったときの戻し方

管理画面に入れなくなった場合は、次のどちらかで戻せる。

- `.env` に正しい `SITE_URL` を書く（システム設定より優先される）
- DB の `modx_system_settings`（接頭辞はサイトによる）で `setting_name='fixed_site_url'` の値を空にし、`php evo cache:clear` で `basicConfig.php` を作り直す（空なら今までの動きに戻る）

## 補足

- ページのキャッシュには、サイトの URL を含む HTML が残る。設定を変えたら、キャッシュを消す（システム設定の保存で消える）
- Wayfinder のリンクは、既定ではサイトの URL を付けず、`/news/` のようにルート相対で出す（`&fullLink` の既定値は FALSE。1.3.0rc1 までは TRUE で、サイトの URL から出していた）。ngrok や Cloudflare Tunnel などで公開すると、サイトの URL が内側の URL のままになりやすいため。サイトの URL から出したいときは `&fullLink=1` を指定する（`&fullLink=TRUE` も同じ。スニペットのパラメータの `true` / `false` は大文字小文字を問わず真偽値として扱われる）
