# 管理画面の文言

管理画面とインストーラーの日本語の文言の書き方。対象は `manager/includes/lang/japanese-utf8.inc.php`・`install/langs/japanese-utf8.inc.php`・`manager/includes/lang/country/japanese-utf8_country.inc.php`。
言語ファイルに設定の文言を足す手順は `global-settings.md`、ダイアログの文言を JS へ渡す方法は `manager-dialog.md` を参照する。

## 書き方

- 短く言い切る。説明は「何が起きるか」と「その条件」だけを書く
- 設定の説明は「「はい」にすると、〜します。」の形にする。説明の冒頭で見出し（設定名）を繰り返さない
- 意味（起きること・条件）を変えるときは、実装を読んで確かめる。文言が実装と食い違っていたら、実装に合わせる

避ける言い回し:

| 避ける | 書く |
| --- | --- |
| 〜することができます | 〜できます |
| 〜を行う・〜を実施する | 動詞で書く（「テストを行ってください」→「テストしてください」） |
| 無事に成功しました・正常に完了しました | 完了しました・〜しました |
| 〜のでご注意ください・注意が必要です | 何が起きるかを書く（「〜すると、〜のおそれがあります」） |
| 〜するかどうかを選択します | 〜します（「はい」にしたときの動きを書く） |
| ※〜（念押しの前置き） | 本文に入れる。補足として分けたいときだけ ※ を残す |
| お手数ですが・〜いただきます | 付けない |

## 表記

- 長音を付ける: ユーザー・サーバー・フォルダー・ブラウザー・パラメーター・エディター・マネージャー・インストーラー・カテゴリー・ヘッダー・セレクター・プロセッサー
- かなで書く: すべて・ください・そろえる。「行なう」ではなく「行う」と書く
- 版を上げることは「アップデート」と書く（「アップグレード」と混ぜない）
- 括弧: 日本語を含むものは全角の（）、英数字だけを囲むもの（`(php)`・`(Public)`）は半角
- テンプレートのタグの記法（`[(コンフィグ変数)]`・`[*リソース変数*]`・`[+プレースホルダー+]`）は記号を変えない
- 日本語の文末の疑問符は全角の「？」
- 確認ダイアログは「〜しますか？」と聞き、影響があれば次の文で書く（例:「このリソースを削除しますか？\nサブリソースもすべて削除されます。」）。影響が起きるときだけ書く（リソースの削除は、子があるときだけ 2 行目を足す。言語ファイルでは `confirm_delete_resource` と `confirm_delete_resource_children` の 2 つのキーに分ける）

## 呼び方

- 画面・ボタン・タブ・設定の名前は、画面に実際に出る文言（その言語キーの値）と同じにする。かぎ括弧で名前を挙げるときは、言語ファイルで値を確かめる（例: ロック画面のボタンは `home` の値の「ダッシュボード」）
- リソースを編集する画面は「投稿画面」と呼ぶ
- 人は「ユーザー」と呼ぶ（「メンバー」と混ぜない）。ウェブユーザーと分けたいときだけ「ウェブユーザー」と書く

## HTML と装飾

- 言語ファイルに `style` 属性を書かない。色や太さはテーマに従わせる
  - 管理画面の強調: `fail`（エラー色）・`warning`・`success`（`manager/media/style/common/theme-base.css`）
  - インストーラーの強調: `span.ok`・`span.notok`（`install/style.css`）
- タブの中の説明に、タブ名を繰り返す見出しを入れない
- 文言の中のタグは、表示する側で囲むタグ（`<p>` など）と組み合わせて正しい HTML になるようにする（開始タグと終了タグを片方だけ置かない）

## リンク

- 検索結果（Google 検索・サイト内検索）へのリンクにしない。日本語の公式の説明に向ける（PHP は `php.net/manual/ja/`、HTML は MDN の日本語版、MODX は `modx.jp/docs/`）
- リンクを足す・直すときは、開けることを確かめる

## 国名

- 外務省の表記に合わせる
- 国番号はユーザーの情報に保存されるため、無くなった国や地域の行も消さない（消すと、選んでいたユーザーの表示が空になる）

## 変えるときの確かめ

- 変更の前後で、キーごとにプレースホルダー（`%s`・`%d`・`[+x+]`・`[(x)]`・`[*x*]`）、HTML タグ、`\n` の数を比べる。違いが出たら、意図した変更かを確かめる
- 文言そのものを判定に使っているコードやスクリプトを grep し、合わせて直す（例: `.claude/skills/adaptive-validation-runner/scripts/setup-site.js` は、インストール完了の文言で成否を判定する）
- 同じキーを二度定義しない（PHP の配列では後の定義だけが効き、前の定義は黙って無視される）
- 新しいキーは日本語と英語の言語ファイルの両方に足す（国名のファイルを除き、片方にしか無いキーは CI の `.github/scripts/lang-key-lint.php` が検出する）
- `php -l` を検証用のイメージの PHP で通し、表示は Docker の検証環境で確かめる（`adaptive-validation-runner` スキル）
