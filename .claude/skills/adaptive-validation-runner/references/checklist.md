# Validation Checklist

## 必須

1. 先に `cli` モードを試した
2. 期待結果を 1 文で定義した
3. 実行したコマンド・スクリプトと、結果の要点を対応付けた
4. 判定を `PASS` / `FAIL` / `UNCONFIRMED` で明示した
5. 管理画面の確認では `Accept-Language` ヘッダーを付けた
6. 不具合修正では、main で再現すること、対象ブランチで解消することの両方を確かめた（できない場合は理由を書いた）
7. ブランチを切り替えたあと、数秒待ってから確かめた
8. 投稿テストでは、保存後に `content` カラムを DB で確かめた（`content_len > 0`）
9. 後片付けを済ませた（または、ユーザーの目視のために残すと伝えた）

## ブラウザモードに切り替える条件

- CLI だけでは判定できない（画面の構造、JS の動作、ダイアログ、遷移）
- 画面の崩れや見た目の差を確かめる必要がある
- ユーザーが目視での確認を明示した

モードの決まりは `.claude/skills/adaptive-validation-runner/SKILL.md` の「モード」に従う。

## 記録するもの

- 実行環境（検証環境のプロジェクト名、ブランチ、変更した設定）
- 観測値（URL、ステータス、応答ヘッダー、DOM の要素数、ダイアログの文言、メールのヘッダー）
- スクリーンショットの保存先（作業用ディレクトリ）
- 条件 × main × 対象ブランチの結果表

投稿テスト（RTE あり）の手順は `.claude/skills/adaptive-validation-runner/SKILL.md` の「投稿テスト」に従う。
